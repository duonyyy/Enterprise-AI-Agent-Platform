# SPEC-KNOWLEDGE-001 — Knowledge Management, Document Ingestion & RAG
**Status:** IMPLEMENTATION SPEC / NOT VERIFIED · **Version:** 1.0 (2026-10-30) · **Database:** `DB-BASELINE-56` (target) · **Priority:** P1 · **Owner:** Control API / Knowledge + jobs-worker; runtime read-only

## 1. Mục tiêu, phụ thuộc và ranh giới

Xây Knowledge Base có kiểm soát quyền, quản lý tài liệu, phiên bản nội dung, ingestion pipeline, chunking, embedding và retrieval có trích dẫn nguồn. PostgreSQL là system-of-record; object storage lưu original bytes; Qdrant chỉ là chỉ mục truy xuất và phải hỗ trợ rebuild. MVP xử lý tài liệu được allowlist (ví dụ .txt, .md, .pdf qua text extractor đã kiểm định); không hỗ trợ file thực thi.

**Phụ thuộc:** DB Foundation + `SPEC-SECURITY-001`, Model Gateway embeddings (nếu dùng), `SPEC-AGENT-001` capability binding

**Không nằm trong scope:** Tự động crawl Internet; arbitrary file execution; document-fine-grained ABAC outside existing base_grants without ADR; embedding storage as second source of truth; unvalidated SQL/vector queries generated by LLM.

## 3. Luồng hoạt động và domain invariants

1. Tạo base và grant bởi authorized principal. Upload nhận bytes vào staging object key theo scope tenant/workspace; kiểm tra size, content-type, magic bytes, malware nếu có; không dùng tên file làm object key trực tiếp.
2. Transaction DB tạo `documents` / `document_versions` / `ingestion_jobs` (đúng lifecycle `CHECK` trong SQL), enqueue outbox. Job dùng leased claim, có retry bounded.
3. Worker lấy object bằng trusted backend, extract text an toàn (sandbox khi cần), chuẩn hóa nội dung Unicode, đánh mã source spans, chia chunk theo chunker_version (hỗ trợ Markdown Heading Chunking bảo toàn cấu trúc ngữ pháp tài liệu). Chunk IDs/deterministic hashing dùng cho dedup; hash không phải raw secret. Lưu vết Raw Artifacts trong object storage để hỗ trợ tái lập và phục hồi dữ liệu khi xảy ra lỗi dữ liệu (Data Observability & Self-Repair).
4. Embedding qua approved model config; ghi `knowledge.chunks`/`vector_refs`, upsert Qdrant idempotent theo point ID; payload gồm `tenant_id,workspace_id,base_id,document_version_id,chunk_id,published` và quyền lọc tối thiểu. Hạn chế lưu raw text trong Qdrant payload nếu không cần.
5. Công bố version chỉ sau khi kiểm tra số chunk/vector, consistency gate, grant và object tồn tại. Nếu Qdrant lỗi, job đánh dấu retryable và published state không được thể hiện thành ready sai.
6. Retrieval ở runtime: principal → danh sách base được bind/granted → filter tenant/workspace/base/documentVersion published → Hybrid Search (kết hợp Dense Vector và Lexical BM25 thông qua thuật toán Reciprocal Rank Fusion RRF với hằng số $k=60$) → Cross-Encoder Reranker lọc Top-20 xuống Top-5 ứng viên → ACL **recheck từ DB** → Citation Verifier đối chiếu span văn bản gốc để sinh trích dẫn có căn cứ `(document_id, version_id, chunk_id, ordinal, source span)`.
7. Deletion/retention: tombstone DB trước, ngăn query mới, xóa Qdrant/object theo event idempotent; kiểm tra legal hold/retention. Reconciliation phát hiện vector orphan/missing.
8. Text từ tài liệu được đánh dấu *untrusted evidence*, tuyệt đối không biến thành system instruction hay cấp tool permission.

**Isolation invariant:** truy vấn không bao giờ vector-search thiếu `tenant_id` + `workspace_id` và kiểm tra base grants. Cùng tên tài liệu ở hai tenants không thể rò chunk. Qdrant payload indexes trên các filter thường dùng và cần benchmark thực tế, không khẳng định index SQL thay được Qdrant index.

API routes là **đề xuất contract** cho đến khi `contracts/openapi/control-api.openapi.yaml` được duyệt. Không tạo endpoints mới nếu tương đương đã tồn tại.

## 5. Structured contracts, validation và trạng thái

`contracts/jsonschema/knowledge-search.v1.schema.json`: `query` (length capped), `baseRefs` subset of authorized binds, `topK` (bounded), `filters` allowlisted. Output `items[]` includes `chunkId`, `documentVersionId`, `score`, `citation`, `sourceTrust='untrusted'`; no guarantee generated answer citation automatically proves truth. `ingestion-job.v1` event includes `jobId`, `status` from existing SQL, counts and safe errorCode.

Storage consistency is **eventually consistent**: SQL publish state must not overstate vector availability. Embedding model changes require new vector refs/reindex and must never mix dimensions or embedding model silently. Optional hybrid lexical+sparse search is subsequent ADR; MVP semantic retrieval + metadata filtering first.

## 7. Security, privacy và kiểm soát quyền

Enforce ACL twice: at base listing and after retrieval, before showing chunks; tenant-aware Qdrant filter is *defense in depth*, not full substitute for authorization. Restrict source URL ingestion to safe allowlisted domains, SSRF/DNS rebinding protection or postpone URL ingestion for MVP. Scan document bytes; parser sandbox for complex/untrusted file formats. Reject prompt instructions embedded in chunks when deciding permissions. Do not put raw document text, presigned URLs or keys into audit/traces. Apply retention and PII classification from Governance.

## 8. Lỗi, retry, idempotency và recovery

`ingestion_jobs` state must use actual SQL `CHECK` values. On partial upsert, resume from deterministic chunk/vector IDs and reconcile; never publish a half-indexed version. Separate transient 429/5xx embedding retries (bounded backoff/jitter) from permanent parser errors. Object store timeout or Qdrant timeout not a reason to return cross-tenant search fallback. On delete, pending purge should suppress retrieval immediately even before physical delete. Queue retry with poison-message quarantine handled without inventing new table.

## Cross-cutting rules (bắt buộc)

- **Source of truth:** `docs/00-governance/CANONICAL_DATABASE_56.md` và 50-table `references/ENTERPRISE_AGENT_PLATFORM_0001_BASELINE.sql`; 3 bảng Skill và 3 bảng MCP là migration mở rộng, **chưa xác nhận chạy thật**. Tổng 56 domain tables là TARGET, không phải production claim. Các bảng framework/checkpointer nội bộ nếu có phải kiểm kê và cách ly, không giả vờ nằm trong 56.
- **Tenant boundary:** derive `tenant_id` từ authenticated principal; xác minh `workspace_id`, ACL, RLS (khi tồn tại) bằng DB role không `BYPASSRLS`; không tin ID hoặc claim do model cung cấp. Object storage, cache, Qdrant, event streaming phải áp cùng scope.
- **Immutability:** AgentVersion, WorkflowVersion, SkillVersion, ToolVersion, eval dataset versions đã publish là immutable; run pin exact version. Nếu phải thêm cột/index/bảng mới, viết ADR + migration review; **không tự tạo bảng domain thứ 57**.
- **Authority:** LLM/Skill/RAG/MCP output là dữ liệu không đáng tin; không được tự tạo grants. Tool side effects bắt buộc đi qua `SPEC-TOOL-001` / policy `SPEC-SECURITY-001`; HITL qua `SPEC-WORKFLOW-001`.
- **Evidence:** code/DDL/documentation khác với triển khai chạy thật. Từng PR phải báo `PASS` / `FAIL` / `BLOCKED` / `NOT_RUN` cùng câu lệnh test và bằng chứng; không được ghi PASS chỉ vì đã viết mock hoặc file spec.
- **No duplicate services:** `control-api` là modular monolith, `agent-runtime` là execution plane; `studio-web` là UI. Tái sử dụng các module, contracts, migration tooling đang tồn tại trước khi tạo tên thư mục mới.
